# UMIR — фронтенд для неизменённого Useless-Corpse API

Этот архив содержит **только React/Vite**, бэкенд менять не требуется.

## Запуск на Windows (PowerShell)

1. Запусти бэкенд Useless-Corpse отдельно на `http://localhost:5067` (со своими PostgreSQL и Redis).
2. Перейди в папку `frontend`:

```powershell
cd frontend
npm ci
npm run dev:live
```

3. Открой `http://localhost:5173`.

`frontend/.env.live`:

```env
VITE_DATA_MODE=live
API_PROXY_TARGET=http://127.0.0.1:5067
VITE_ENABLE_REALTIME=true
```

Если поменяешь порт бэкенда, измени `API_PROXY_TARGET`, останови Vite и запусти заново.

## Где конструктор продуктов и меню

В ресторане открой **Настройки → Редактор продуктов и меню** или вкладку **Редактор меню** рядом с настройками.
Все поля — **черновик браузера**, который сохраняется локально. API не предоставляет полноценное чтение исходного каталога. Импортируй полный актуальный набор данных перед публикацией действующего ресторана.

«Отправить всё» → «Окей, отправить» вызывает **последовательно** `POST /api/Restaurant/SetProducts`, затем `POST /api/Restaurant/LoadRestaurantMenu`. Эндпоинты бэкенда заменяют каталоги целиком. Это не единая транзакция, поэтому возможна частичная запись.

## Другие возможности

В настройках владелец может показать и скопировать API-ключ поставщика (ключ запрашивается через `GetUserRestaurants`, не хранится в localStorage). Регистрация POS-терминалов теперь находится **на вкладке «Сотрудники»**. Приём приглашений доступен через список ресторанов.

SignalR-клиент слушает `ProductsUpdated`, `StopListUpdated`, `RecommendationsUpdated`, `AnalyticsUpdated` и, при их появлении на бэкенде, `SuppliesUpdated`/`SupplyArrived` по `/hubs/notifications` через Long Polling. Для работы бэкенду необходимо проверять членство в ресторане при `JoinRestaurant`, включить `UseAuthentication()` перед `UseAuthorization()`, отправлять начальный снимок состояния и публиковать события при изменениях.

## Склад и приёмка

Склад переключается между суммой по продуктам и отдельными FoodStock-строками по поставкам.
Приёмка показывает реальные приехавшие продукты при наличии полного серверного события; в текущем исходном API **нет метода чтения ожидающих поставок**, поэтому предусмотрена ручная форма по UUID. Три кнопки: «Отказ», «Принять» из полей и «Принять всё» из приехавших количеств. Подробнее в `CHANGES_2026-10-16_UI_DELIVERIES.md`.
